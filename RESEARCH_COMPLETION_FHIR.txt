================================================================================
KEY FINDINGS SUMMARY
================================================================================

FINDING 1: Authorization Code Flow is Universal
- 99% of healthcare SaaS use this pattern
- PKCE is mandatory in production
- Backend for Frontend essential for security
- Token refresh must be automatic

FINDING 2: Multi-Tenant Architecture Required
- Every token query must include tenant_id
- One user can have multiple EMR connections
- Each EMR instance = separate OAuth2 client
- Database schema must enforce isolation

FINDING 3: SMART on FHIR is Standardized
- Epic, Cerner, OpenEMR all follow FHIR R4
- Well-known endpoint enables discovery
- Same FHIR resources across EMRs
- Scopes are standardized but some EMR-specific

FINDING 4: Backend Services Separate from User Auth
- JWT-based authentication for system access
- No user login required
- Short-lived tokens (60-300 seconds)
- Different scopes (system/* instead of patient/*)

FINDING 5: Token Lifecycle Management Critical
- Encrypt at rest (AES-256-GCM)
- Refresh before expiration (5-min buffer)
- Revoke on logout
- Audit every access

FINDING 6: Error Recovery Patterns Standard
- 401 (expired): Refresh and retry
- 429 (rate limit): Exponential backoff
- 500+ (server error): Exponential backoff
- 403/404: Don't retry

FINDING 7: Production Timeline Realistic
- 6-10 weeks to production system
- 3-12 months per customer (their approval)
- Complexity scales with EMR count
- Once first EMR done, others easier
